# Trine 产品设计规范

Trine 是供长时间使用的远程 AI 工作台。设计以任务连续性、信息可读性和操作确定性为先。视觉方向为「精密工作台」：冷中性色建立层次，青色标识当前操作与选择，等宽字体只用于技术元信息。避免霓虹、玻璃叠层、大面积渐变和持续装饰动画。

## 信息架构与空间

- 会话是主任务，机器是会话的运行位置，扩展是任务的辅助能力。设置承载低频偏好。
- 小于 900px 使用列表 → 会话的单页导航；返回保持列表筛选和草稿。不加入与输入区争抢空间的底部导航。
- 900px 起采用常驻 300px 侧栏；1100px 起侧栏 320px，主工作区以 12px 外边距及圆角形成独立面板。断点与 `useIsDesktop` 保持一致。
- 桌面侧栏顺序为品牌与连接状态、新建会话、工作空间过滤、列表控制、会话、维护入口。主要动作靠近顶部，刷新、机器、设置位于底部。
- 对话内容与桌面输入卡片共享 960px 阅读宽度，宽屏以对称留白控制行长；代码在自身区域横向滚动。工具与扩展面板根据任务需要使用空间，不套用对话阅读宽度。
- 移动端输入保持紧凑，辅助动作放入「+」托盘；桌面显示直接工具入口和发送快捷键。触屏回车换行，以明确按钮发送。

## 视觉基础

颜色唯一来源为 `apps/web/src/styles.css`，使用语义工具类，不在业务组件硬编码色值。浅色以雾灰背景和白色表面区分区域；深色以石墨灰分层，避免纯黑纯白强烈对比。主题继续支持系统、浅色、深色。

| 角色 | 使用 |
| --- | --- |
| background / surface / surface-2 | 外壳 / 主面板与卡片 / 次级填充 |
| text / text-2 / text-3 | 正文 / 说明 / 次要元信息 |
| brand / brand-soft / brand-border | 主操作 / 选择背景 / 选择边界 |
| amber | 等待授权、需要用户注意 |
| red | 错误与破坏操作 |
| green / blue | 成功、信息状态，均需附文字或图标 |

强调色不用于整段正文。状态不得仅靠颜色表达。正文正常字号对比目标 4.5:1，关键非文字边界目标 3:1；新增配色需重新检查。元信息并非禁用内容，保持可读，不随意降低 opacity。

字体使用本地 IBM Plex Sans / Mono，中文使用系统回落，不请求第三方字体。正文 14px、行高 1.55；较长解释使用 1.75–2。标题 15–24px、600 字重；元信息 11–12px，避免堆叠技术缩写。间距以 4px 为基准，常用 8/12/16/24/32；卡片约 12px、工作面板 16px 圆角，只有 chip 和状态点使用胶囊或圆形。

## 组件约定

| 组件 | 规范 |
| --- | --- |
| Button | 同一局部只突出一个主动作；次级操作用 outline 或 ghost；图标按钮必须有 aria-label，桌面可附 tooltip |
| 表单 | 可见标签、说明、就近错误；placeholder 不代替标签；保留用户失败前输入 |
| 会话行 | 标题第一层，预览第二层，机器、引擎、时间第三层；当前会话使用品牌边框和浅填充，待授权保留警示语义 |
| AppHead | 标题、元信息、局部操作；移动端返回提供 44px 点击区域，桌面避免无意义的返回列表入口 |
| Composer | 桌面输入卡片与正文对齐；移动端留安全区；发送、排队、停止保持不同语义，运行中仍可输入 |
| 空态 | 解释当前状态并给出下一步；工作台初始空态提供新建入口，搜索无结果提供调整过滤的指引 |
| Sheet / Dialog | 沿用 Radix 的焦点约束、Escape 和焦点恢复；手机优先底部 sheet，桌面适当限制宽度；长内容内部滚动 |
| 通知 | 连接状态属于全局，授权属于当前任务；临时结果使用 toast，必须处理的错误留在上下文中 |

不要把破坏操作放在主按钮旁无区分地展示；恢复代码、撤销配对、权限确认沿用现有确认流程。视觉调整不能降低权限可见性或跳过确认。

## 输入与反馈

触控 Button、菜单项、选择器至少 44px 高，图标按钮至少 44px 宽；内联文本动作需按具体密度单独检查。桌面可以使用紧凑控件，但鼠标悬停不是发现操作的唯一方式。所有操作必须可用键盘完成并有可见焦点，选择状态与 hover 状态区分。

反馈以 120–200ms 的颜色、透明度变化为主，避免布局跳动；尊重 prefers-reduced-motion。加载区保持布局，断线解释排队行为，提交失败给可执行的重试路径。长输出不得推动固定输入区离开屏幕。

## 迭代验收

新增视图首先复用 AppHead、Button、Input、Sheet、SessionRow 与语义 token。若新增组件模式，在本文件补充适用范围后再推广。检查 390px、768px、900px、1440px 下的布局，并覆盖浅色、深色、键盘、触控、长标题、空数据、错误、离线及待授权状态。禁止横向页面溢出；允许代码区域自身滚动。UI 截图和测试仅使用合成数据。

本轮实现覆盖全局主题、桌面外壳和侧栏、页头、会话行、工作台空态、对话阅读宽度、输入卡片对齐及共用控件的触控尺寸。配对、权限、重放防护和传输协议维持既有流程。复杂业务组件继续沿用现有行为，后续变更按本规范逐步收敛。

## 参考依据

采用原则并按 Trine 的任务结构调整，并未复制组件源码：

- [Material 自适应布局](https://developer.android.com/design/ui/mobile/guides/layout-and-content/adapt-layout)：按可用空间调整面板组织。
- [Carbon 空态](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states)：解释状态并引导下一步。
- [Carbon 输入框](https://www.carbondesignsystem.com/building-blocks/core/components/text-input/guidelines)：标签、辅助文本及错误提示保持明确。
